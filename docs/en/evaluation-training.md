# Evaluation-weight training pipeline (Phase 4)

The evaluation function is trained from games end-to-end: Rust extracts
training positions (it owns the Edax-faithful B4 canonicalisation), Python
fits the per-stage linear model (design doc §4.4 B3), and Rust loads the
learned weights for play. The on-disk weight format is `LGW1`, a fully
explicit little-endian layout that Rust and Python write/read
**byte-identically** (see
[`WEIGHTS_FORMAT.md`](../../crates/logistello-eval/WEIGHTS_FORMAT.md)); the
extract format is the columnar `PEX1`
([`EXTRACT_FORMAT.md`](../../crates/logistello-eval/EXTRACT_FORMAT.md)).

## 1. Extract training positions

`extract` emits the `PEX1` columnar binary the Python `train-eval` tool
consumes.

```bash
# a) self-play (deterministic, no external data — the test vehicle):
cargo run --release -p logistello-cli -- extract \
    --source selfplay --games 300 --seed 1 --output /tmp/pos.bin

# b) OR real WTHOR expert games (manual download, design doc §4.5 B5):
#    curl -L -o WTH_2004.ZIP \
#      https://www.ffothello.org/wthor/base_zip/WTH_2004.ZIP
#    unzip WTH_2004.ZIP -d data/wthor/
cargo run --release -p logistello-cli -- extract \
    --source wthor --wthor-dir data/wthor/ --output /tmp/pos.bin
```

| Flag | Meaning | Default |
|---|---|---|
| `--source` | `selfplay` (seeded, no external data) or `wthor` (real `.wtb` games) | `selfplay` |
| `--wthor-dir` | Directory containing `.wtb` files (required for `--source wthor`) | — |
| `--games` | Number of self-play games / max WTHOR games | `2000` |
| `--seed` | Self-play RNG seed (deterministic) | `42` |
| `--max-empties-skip` | Skip positions with more than this many empty squares (drop the very opening) | keep all |
| `--output` | Output `PEX1` file (required) | — |

## 2. Train the per-stage linear eval

`train-eval` fits the faithful B3 GD-300 model by default; `--method
ridge|sgd` selects the scikit-learn least-squares §7 comparison paths.

```bash
uv run logistello-tools train-eval \
    --positions /tmp/pos.bin --output /tmp/w.lgw1 --method gd
```

| Flag | Meaning | Default |
|---|---|---|
| `--positions` | Input `PEX1` extract file (from `logistello extract`) | required |
| `--output` | Output `LGW1` weight file | required |
| `--method` | `gd` = faithful B3 GD-300 with rare-config muting; `ridge` / `sgd` = scikit-learn least-squares (§7 comparison) | `gd` |

## 3. Play using the learned pattern evaluator

```bash
cargo run --release -p logistello-cli -- play \
    --black engine --white random --depth 4 --seed 42 \
    --eval-weights /tmp/w.lgw1
```

Without `--eval-weights`, `play` uses the Phase 3 `BasicEval` (disc count +
mobility); with it, the engine uses the learned Edax-style `PatternEval`.

> **Honest notes (B3):** the default `gd` method is the faithful Buro B3
> GD-300 gradient descent with rare-configuration muting — not a generic
> least-squares solver. `--method ridge|sgd` are scikit-learn comparison
> paths from design doc §7, intentionally *not* the canonical learner. The
> 13-stage per-disc-count model and the Edax-faithful B4 canonicalisation
> live on the Rust `extract` side (Rust owns canonicalisation; the Python
> `wthor-extract` subcommand is deliberately delegated to Rust `extract`).
