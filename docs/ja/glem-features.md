# GLEM 自動生成特徴量

GLEM（一般化線形評価モデル，Buro 1998 CG'98）は基底リテラル集合上に連言
特徴を自動生成し，その上で線形モデルを学習する．Rust が基底リテラル抽出を
担い（`extract` の「Rust が正規化を担う」と同様），Python が連言を
生成してモデルを学習する．`GLX1` 抽出 / `GLM1` モデル形式は
[`GLEM_FORMAT.md`](../../crates/logistello-eval/GLEM_FORMAT.md)を参照．

## 1. GLEM 基底リテラル局面を抽出する

`glem-extract` は Python の `train-glem` ツールが消費する `GLX1` 列指向
バイナリを出力する．

```bash
cargo run --release -p logistello-cli -- glem-extract \
    --base-features cell64,mobility,corner \
    --source selfplay --games 2000 --seed 42 \
    --output /tmp/glem.glx1
```

| フラグ | 意味 | 既定値 |
|---|---|---|
| `--base-features` | 基底特徴ファミリのカンマ列（`cell64`,`mobility`,`corner`）．順序 = `GLX1` / `GLM1` に記録される spec id | `cell64,mobility,corner` |
| `--source` | `selfplay`（シード付き，外部データ不要）または `wthor` | `selfplay` |
| `--wthor-dir` | `.wtb` ファイルを含むディレクトリ（`--source wthor` で必須） | — |
| `--games` | 自己対局数 / 最大 WTHOR 棋譜数 | `2000` |
| `--seed` | 自己対局 RNG シード（決定的） | `42` |
| `--max-empties-skip` | この空きマス数を超える局面をスキップ | 全保持 |
| `--output` | 出力 `GLX1` ファイル（必須） | — |

## 2. 連言を生成しモデルを学習する

`train-glem` は GLEM 特徴生成 + B3 線形当てはめを行う．

```bash
uv run logistello-tools train-glem \
    --positions /tmp/glem.glx1 --output /tmp/glem.glm1 \
    --base-features cell64,mobility,corner \
    --max-order 2 --support-threshold 1e-3 --method gd
```

| フラグ | 意味 | 既定値 |
|---|---|---|
| `--positions` | 入力 `GLX1` 抽出ファイル | 必須 |
| `--output` | 出力 `GLM1` モデルファイル | 必須 |
| `--base-features` | 基底特徴ファミリのカンマ列．`GLX1` コーパス spec と一致必須 | コーパス由来 |
| `--max-order` | 最大連言次数 K（§6: 1,2,3,4）．1 = 単純線形 | — |
| `--support-threshold` | τ_support: 生成連言を保持する最小学習頻度（§6: 1e-4 .. 1e-2） | — |
| `--weight-threshold` | τ_weight: 最大 |weight|（石単位）がこれ未満の特徴を枝刈り．0 で全保持 | `0` |
| `--method` | `gd` = ミュート付き忠実 B3 GD-300; `ridge`/`sgd` = scikit-learn 最小二乗（§7）; `logistic` = 任意の Logistello-1 パス（Objective-5 専用） | `gd` |

## 3. GLEM モデルで対局する

```bash
cargo run --release -p logistello-cli -- play \
    --black engine --white random --depth 4 --seed 42 \
    --glem-model /tmp/glem.glm1
```

`--glem-model` を指定すると `engine` プレイヤは `PatternEval` /
`BasicEval` ではなく `GlemEval`（自動生成連言特徴）を中盤リーフ評価に
使う．`--eval-weights` とは排他（PatternEval と GlemEval は代替の
リーフ評価器）で，`--probcut` / `--mpc` とは併用できる．

> **正直な注記:** `cell64` 基底ファミリを `--max-order 2` にすると非常に
> 大きな連言空間を生成しうる．生成器は学習を扱える範囲に保つため
> cell64-order2 展開に数値クランプを適用する．これはここに明記する意図的な
> 近似である．**Objective-5** 装置は，同一ホールドアウトコーパス上で GLEM
> 自動特徴と手動 `PatternEval` を比較する（設計ドキュメント §5）．
>
> ```bash
> uv run logistello-tools objective5 \
>     --glx1 /tmp/heldout.glx1 --glm1 /tmp/glem.glm1 \
>     --pex1 /tmp/heldout.pex1 --lgw1 /tmp/w.lgw1
> ```
