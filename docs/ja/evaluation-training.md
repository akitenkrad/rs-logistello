# 評価関数重みの学習パイプライン（Phase 4）

評価関数は棋譜からエンドツーエンドで学習する．Rust が学習局面を抽出し
（Edax 忠実な B4 正規化を担う），Python がステージ別線形モデルを学習し
（設計ドキュメント §4.4 B3），Rust が学習済み重みを読み込んで対局する．
ディスク上の重み形式は `LGW1`（完全に明示的なリトルエンディアン配置）で，
Rust と Python が**バイト同一**に読み書きする
（[`WEIGHTS_FORMAT.md`](../../crates/logistello-eval/WEIGHTS_FORMAT.md)を参照）．
抽出形式は列指向の `PEX1`
（[`EXTRACT_FORMAT.md`](../../crates/logistello-eval/EXTRACT_FORMAT.md)）．

## 1. 学習局面を抽出する

`extract` は Python の `train-eval` ツールが消費する `PEX1` 列指向バイナリを
出力する．

```bash
# a) 自己対局（決定的，外部データ不要 — テスト用）:
cargo run --release -p logistello-cli -- extract \
    --source selfplay --games 300 --seed 1 --output /tmp/pos.bin

# b) または実 WTHOR エキスパート棋譜（手動ダウンロード，設計ドキュメント §4.5 B5）:
#    curl -L -o WTH_2004.ZIP \
#      https://www.ffothello.org/wthor/base_zip/WTH_2004.ZIP
#    unzip WTH_2004.ZIP -d data/wthor/
cargo run --release -p logistello-cli -- extract \
    --source wthor --wthor-dir data/wthor/ --output /tmp/pos.bin
```

| フラグ | 意味 | 既定値 |
|---|---|---|
| `--source` | `selfplay`（シード付き，外部データ不要）または `wthor`（実 `.wtb` 棋譜） | `selfplay` |
| `--wthor-dir` | `.wtb` ファイルを含むディレクトリ（`--source wthor` で必須） | — |
| `--games` | 自己対局数 / 最大 WTHOR 棋譜数 | `2000` |
| `--seed` | 自己対局 RNG シード（決定的） | `42` |
| `--max-empties-skip` | この空きマス数を超える局面をスキップ（序盤を除外） | 全保持 |
| `--output` | 出力 `PEX1` ファイル（必須） | — |

## 2. ステージ別線形評価を学習する

`train-eval` は既定で忠実な B3 GD-300 モデルを学習する．`--method
ridge|sgd` は scikit-learn 最小二乗の §7 比較パスを選択する．

```bash
uv run logistello-tools train-eval \
    --positions /tmp/pos.bin --output /tmp/w.lgw1 --method gd
```

| フラグ | 意味 | 既定値 |
|---|---|---|
| `--positions` | 入力 `PEX1` 抽出ファイル（`logistello extract` 出力） | 必須 |
| `--output` | 出力 `LGW1` 重みファイル | 必須 |
| `--method` | `gd` = 希少構成ミュート付き忠実 B3 GD-300; `ridge` / `sgd` = scikit-learn 最小二乗（§7 比較） | `gd` |

## 3. 学習済みパターン評価で対局する

```bash
cargo run --release -p logistello-cli -- play \
    --black engine --white random --depth 4 --seed 42 \
    --eval-weights /tmp/w.lgw1
```

`--eval-weights` なしでは `play` は Phase 3 の `BasicEval`（石数 + モビリティ）
を使い，指定すると Edax 流の学習済み `PatternEval` を使う．

> **正直な注記（B3）:** 既定の `gd` 法は希少構成ミュート付きの忠実な Buro
> B3 GD-300 勾配降下であり，汎用最小二乗ソルバではない．`--method ridge|sgd`
> は設計ドキュメント §7 の scikit-learn 比較パスで，意図的に正規の学習器
> *ではない*．石数別 13 ステージモデルと Edax 忠実な B4 正規化は Rust の
> `extract` 側にある（Rust が正規化を担う．Python の `wthor-extract`
> サブコマンドは意図的に Rust の `extract` に委譲される）．
