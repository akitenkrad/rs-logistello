# Edax オラクル，Elo，評価相関

Edax v4.6 は固定強度の外部対戦相手／非対局オラクルである．プラットフォーム
バイナリと数 MB の評価重みを伴うため，**決してコミットしない**（`.edax/`
は gitignore）．Edax を駆動するサブコマンドは `.edax/` がない場合は
**スキップして通知を表示する**（捏造しない）ので，Edax のないマシンでも
ビルドはグリーンを保つ．

## Edax セットアップ

```bash
bash scripts/setup_edax.sh   # Edax v4.6 をビルドし eval.dat を .edax/ へ取得
```

スクリプトは冪等かつ自己完結．完全な再現手順は
[`EDAX_SETUP.md`](../../EDAX_SETUP.md)にある．そこに 2 つの正直な知見を
記録している．

- **macOS `aligned_alloc` 修正:** Edax のハッシュテーブル確保はアライメント
  の倍数でないサイズで C11 `aligned_alloc` を呼ぶ．macOS の
  `aligned_alloc` はこれを厳密に拒否する（glibc は寛容）．セットアップ
  スクリプトは上流様式の `adjust_size` パッチを自動かつ冪等に適用する．
  Linux でも無害である．
- **GTP ドライバの知見:** 固定リビジョンの `rs-othello-sim`
  `GtpProtocol` / `ExternalEnginePlayer` パスは固定リビジョンでは使えない
  （Edax 自身の手を誤った色で再 `play` する）．そこで Edax は，Edax
  自身の手を再生しない**直接 GTP の `EdaxGtpSession`**で駆動する
  （`? wrong color` 修正）．

## `elo-vs-edax` — Edax 比 Elo を推定する

`elo-vs-edax` は直接 GTP のフルゲームドライバで各レベルの Edax に対する
Elo を推定する（設計ドキュメント §4.3.8 `elo_vs_edax_level_N`）．Elo 差は
観測スコア `p` から `Δ = -400·log10(1/p - 1)`．**既定では限定実行**
（レベル 1,3 × 2 局）．フルスイープは
[フルスケール再現](full-scale-reproduction.md)に記載．Edax のレベル→絶対
強度の対応は定性的に過ぎない（§5）．

```bash
cargo run --release -p logistello-cli -- elo-vs-edax \
    --edax-levels 1,3 --num-games-per-level 2 \
    --eval-weights results/eval_weights/wthor_medium.lgw1
```

| フラグ | 意味 | 既定値 |
|---|---|---|
| `--edax-path` | Edax バイナリのパス | `.edax/edax` |
| `--edax-levels` | Edax `-level N` 強度のカンマ列 | `1,3` |
| `--num-games-per-level` | レベルあたり局数（色バランス．偶数に切上げ） | `2` |
| `--eval-weights` | 本エンジン `PatternEval` の `LGW1` 重み（なければ `BasicEval`） | — |
| `--depth` | 本エンジンの選択的中盤深さ（デモ用に小さく） | `6` |
| `--endgame-empties` | 本エンジンの厳密終盤切替閾値（空きマス） | `16` |
| `--seed` | 記録されるが結果は決めない（下記） | `42` |
| `--output` | レベル別表の CSV を run の外にもう 1 部書く（任意） | — |

実行は runvault の run として記録される．レベル 1 つが
`x.logistello.edax_level` イベント 1 行（旧 `elo_vs_edax.csv` の 1 行に
対応: `games` / `wins` / `draws` / `losses` / `score_rate` / `win_rate` /
`elo_delta`）で，`metrics.csv` には観測主体の数 `n_units`（= レベル数）
だけを置く．Edax はバイナリと評価重み `eval.dat` の **両方**を内容
ハッシュで `data` に載せる — どちらが違っても出る数が変わるためである．

`--seed` は受け取って記録するが**何も決めない**（本エンジンは決定的で，
Edax は book 無効・単スレッドで動かす）．そのため `config_hash` からは
外してあり（同じ条件の run が 2 つの条件に割れないように），分野も
`simulation` ではなく `analysis` である（駆動しない `master_seed` を
名乗らない）．

## `eval-correlation-edax` — 本評価と Edax の相関

`eval-correlation-edax` は，限定局面集合上で本 `PatternEval` の値と Edax
評価との Pearson 相関を報告する（設計ドキュメント §4.3.8
`eval_correlation_edax`，Edax を真値とする）．

```bash
cargo run --release -p logistello-cli -- eval-correlation-edax \
    --edax-level 6 --positions 24 \
    --eval-weights results/eval_weights/wthor_medium.lgw1
```

| フラグ | 意味 | 既定値 |
|---|---|---|
| `--edax-path` | Edax バイナリのパス | `.edax/edax` |
| `--edax-level` | `genmove` ベース評価に使う Edax 固定強度 | `6` |
| `--eval-weights` | 本 `PatternEval` の `LGW1` 重み（なければ `BasicEval`） | — |
| `--positions` | サンプル局面数（限定） | `24` |
| `--seed` | 決定的局面ウォークのシード | `42` |
| `--output` | 標本表の CSV を run の外にもう 1 部書く（任意） | — |

標本 1 局面が `x.logistello.eval_sample` イベント 1 行（`our_score` /
`edax_score`），Pearson の `r` と標本数 `n_units` が run スコープ指標で
ある．`r` は `n < 2` や分散 0 では**定義できない**ので，その場合は行を
書かない（0 で埋めない）．標本局面は種つきのランダムウォークで選ぶので，
こちらの分野は `simulation`（`master_seed` = `--seed`）である．

> **注意（正直な注記）:** コミット済みの簡易実行は *中規模* の WThor 学習
> 重みを使うため，Elo は §5 ／歴史的目標より弱い．
> [フルスケール再現](full-scale-reproduction.md)を参照．
